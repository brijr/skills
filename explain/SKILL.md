# Explain and coach

Use the user's requested depth and target. For an ordinary explanation, answer directly with relevant examples; do not start a quiz, require a restatement, or create a document.

For explicit coaching, practice, or mastery requests, read [coaching guidance](references/coaching.md). Establish the learning objective from context, teach a manageable piece, and check understanding with a relevant exercise. Adapt to the user's answers rather than requiring every stage for every concept.

Ground code explanations in the actual implementation when available. Separate verified behavior from assumptions. Use diagrams or examples when they reduce confusion, and avoid unrelated repository exploration.

Create a learning document only when requested. A request for a simple answer, a change of topic, or a stop ends the coaching loop.
